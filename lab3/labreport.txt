Для модульного/unit тестирования я использовал фреймворк Catch2.
Изначально подключил его как git сабмодуль:
    git submodule add https://github.com/catchorg/Catch2.git lab3/third_party/Catch2
когда пишешь git submodule add <url> <path>, git делает два дела:
    1) клонирует репозиторий Catch2 в указанную папку - в lab3/third_party/Catch2;
    2) + запись в .gitmodules чтобы Git + другие разработчики знали что это за подмодуль и откуда он берется.
мой .gitmodules:
    [submodule "lab3/third_party/Catch2"]
    	path = lab3/third_party/Catch2
    	url = https://github.com/catchorg/Catch2.git
    здесь написано:
        имя подмодуля
        path - куда клонирован локально Catch2
        url - откуда подмодуль был скачан

при сборке проекта Catch2 берется из локальной папки. В lab3/tests/CMakeLists.txt написано:
    add_subdirectory(${CMAKE_SOURCE_DIR}/third_party/Catch2 ...)
    то есть CMake подключает Catch2 как локальную директорию, сети при сборке не нужно ибо локально все нужное уже лежит.

Чтобы не требовать от пользователя вручную инициализировать сабмодуль (как изначально делал я), добавлен скрипт
get_dependencies.sh который клонирует Catch2 в third_party/Catch2 только если:
    - папки еще нет
    - установлена переменная окружения WITH_TESTS
В CMakeLists.txt добавлен option(WITH_TESTS ...). Когда передаётся -DWITH_TESTS=ON,
CMake на этапе конфигурации вызывает скрипт через execute_process(), затем подключает тесты.
Таким образом достаточно одной команды cmake .. -DWITH_TESTS=ON и зависимости подтянутся сами.



Архитектура:
    Atom (что будет матчится с введенными строками):
        1) LiteralAtom - конкретный символ: 'a', 'B', '3', ' '
        2) AnyAtom - любой символ: '.'
        3) GroupAtom - набор/диапазон: [abc], [a-z]

    Token = Atom + Modifier (Once/Star/Plus/Question) - это пара "что матчить" + "сколько раз матчить это что-то"

    Regex = вектор токенов + рекурсивный матчер matchFrom()



Regex::Regex(const std::string& pattern)
    конструктор отвечает за парсинг шаблона регулярного выражения. Вызывается в main.cpp для например такого:
        Regex regex("a*[b-d]+")
        в рамках действия конструктора пользовательский шаблон разбивается на мои "токены": атомы и модификаторы и кладется в поле - вектор tokens.

    осуществляется проход по переданному по шаблону слева направо, на каждом шаге создается Atom:
        "[" -> GroupAtom,
        "." -> AnyAtom,
        иначе LiteralAtom).
        Затем в этом же шаге смотрится следующий символ: если это */+/?, то выставляется модификатор.
        Затем токен кладется в вектор токенов.

    Результат: вектор tokens заполнен.
    Пример: для паттерна "a*[b-d]+" в нем два токена: {LiteralAtom('a'), Star}, {GroupAtom("bcd"), Plus}.

std::string parseSet(const std::string& pattern, int& i):
    это вспомогательная функция которая вызывается когда парсер встречает "[";
    разворачивает содержимое строки "[...]" в строку символов. то есть "a-z" разворачивается в "abcde...z"

match(text) - публичная точка входа которая просто зовет matchFrom(0, text, 0) - рекурсивный матчер.

bool Regex::matchFrom(int tokIdx, const std::string& text, int textIdx)
    Это рекурсивный матчинг шаблона и текста. метод принимает три параметра:
        1) tokIdx - какой токен сейчас,
        2) text,
        3) textIdx - где в тексте находимся.

    if (tokIdx == tokens.size()) {
        return textIdx == text.size();
    }
    - это база рекурсии. вызывается когда все токены разобраны. если весь текст пройден то true.
    Далее берется текущий токен из вектора tokens и его атом.
    Затем смотрится модификатор:
        1) Once - один символ:
            if текст кончился ИЛИ символ не совпал → false;
            иначе рекурсия: следующий токен и следующий символ в тексте
        2) Star / Plus - жадные модификаторы:
            счет count: это счетчик который смотрит сколько символов исследуемого текста подряд совпадает с текущим атомом;
            при этом если модификатор атома Plus, то если count == 0 то выдаю false ибо нужен хотя бы один символ в тексте.
            Рекурсия заключается в том что беру следующий токен, а в тексте прыгаю на textIdx + count.
        3) Question - ленивый модификатор - сначала пробует взять в тексте 0 символов, потом 1:
             если matchFrom(tokIdx + 1, text, textIdx) - пропускаю 1 атом и сравниваю следующий с текущим символом в тексте;
             если не вышло:
                 если символ текста совпадает с атомом, то вызываю matchFrom(tokIdx + 1, text, textIdx + 1);
             иначе false.

    Пример 1: шаблон "a?a", текст "a". Первый атом {"a?"} берет 0 символов, а второй атом {"a"} берет символ "a" из текста.
    Пример 2: шаблон "a+", текст "aab":
        matchFrom(0, "aab", 0)
            токен {LiteralAtom('a'), Plus}
            count: 'a'==a ДА, 'a'==a ДА, 'b'==a НЕТ -> count = 2 -> textIdx += 2;
            matchFrom(1, "aab", textIdx=2)
                tokIdx == tokens.size() (1 == 1) значит срабатывает база рекурсии:
                textIdx == text.size()? <=> 2 == 3? НЕТ -> false
          -> "aab" не совпадает с "a+"
