Сборка проекта (без тестов):
    rm -rf build && mkdir build && cd build
    cmake .. -DWITH_TESTS=OFF
    cmake --build . --parallel 8

Сборка проекта (с тестами):
    rm -rf build && mkdir build && cd build
    cmake .. -DWITH_TESTS=ON
    cmake --build . --parallel 8

    При передаче -DWITH_TESTS=ON cmake на этапе конфигурации автоматически вызывает
    скрипт get_dependencies.sh, который клонирует Catch2 в директорию third_party/Catch2 если
    папки ещё нет. Собирать вручную зависимости не нужно (больше) ((прям как у нас в проекте ядра)) (((гойда))).

Запуск тестов (требует сборки с -DWITH_TESTS=ON; запуск происходит в директории build):
    cd tests && ./unit_tests --order decl -s
    (альтернативный запуск через CMake утилиту ctest) ctest --test-dir .

Запуск программы:
    ./res <input-format> <output-format>
    где формат: json | toml | xml (регистр не важен).
    Пример(ы):
        echo '{"a": 1, "abc": 123}' | ./res json json
        echo '{"a": , "abc": 123}' | ./res json json   // вернет "ошибка парсинга в line 1, column 7: unexpected character ','"



внутри класса Value лежит одно поле:
    std::variant<bool, int64_t, double, std::string, Array, Object> data_
    внутри поля data_ в любой момент времени хранится одно значение одного из перечисленных типов данных.
    В value.cpp реализации функций:
        1) как в data_ что-то положить:
            Например: Value::Value(bool value) : data_(value) {}
            Каждый конструктор просто инициализирует data_ переданным значением.
                std::variant сам разбирается какую из шести альтернатив активировать, по типу аргумента.
        2) is_* - что сейчас лежит в этом узле?
            Например: bool Value::is_bool() const { return std::holds_alternative<bool>(data_); }
            std::holds_alternative<T>(variant) - проверка "активна ли сейчас альтернатива типа T?", возвращает true/false.
                Нужны так как когда парсеры будут обходить дерево, то нужно будет решать что в узле до того как доставать значение,
                    то есть например так: if (node.is_object()) { ... } else if ...
        3) as_* - достать значение конкретного типа
            Например: bool Value::as_bool() const { return std::get<bool>(data_); }
            std::get<T>(variant) = "достань значение как T"

    Вопрос: почему не сделать шаблонный конструктор?
    Ответ: чтобы можно было писать Value v = 5; или Value v = "hello"; без явного Value(std::in_place_type<...>, ...).



для тестирования используется библиотека Catch2. Используемые макросы:
    TEST_CASE("описание", "[тег]") объявляет один именованный тест. Тег в квадратных скобках ([json]) это способ
        группировать и потом запускать только часть тестов (./unit_tests [json])
    REQUIRE(условие) - если условие ложно то тест падает и Catch2 печатает что именно не совпало
    REQUIRE_THROWS_AS(выражение, тип_исключения) - тест проходит только если выражение бросает исключение именно этого
        типа. Если оно не бросает вообще, или бросает что-то другое то тест падает
