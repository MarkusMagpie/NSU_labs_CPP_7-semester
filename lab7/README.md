# lab7 — Умная очередь сообщений (брокер + клиентская библиотека)

## Зависимости

```bash
sudo apt install libzmq3-dev cppzmq-dev libyaml-cpp-dev nlohmann-json3-dev
```

## Сборка

```bash
cd ~/Desktop/NSU_labs_CPP_7-semester/lab7
rm -rf build && mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
cmake --build . -j"$(nproc)"
```

## Запуск

```bash
./broker ../config/broker.yaml
```

Брокер ожидает входящие сообщения до остановки через `Ctrl+C`, разбирает
JSON-конверты и выводит их поля. Клиентская библиотека `lab7_client` предоставляет
`BrokerClient`: конструктор принимает адрес, например `tcp://localhost:5555`,
`send()` отправляет строку, а `receive()` ожидает строку-ответ. Экземпляр клиента пока рассчитан на один поток.
`connect()` в ZeroMQ инициирует подключение асинхронно и не подтверждает,
что брокер уже доступен.

### Служебные сообщения M1

Производитель объявляет QoS, например:
`{"type":"declare_producer","producer_qos":"broker_ack"}`.
Значения `producer_qos`: `none`, `broker_ack`, `consumer_ack`.

Потребитель подписывается на существующую очередь, например:
`{"type":"subscribe","queue":"HighPriorityQueue","consumer_qos":"with_ack","ack_timeout_ms":5000}`.
Значения `consumer_qos`: `no_ack`, `with_ack`, `recovery`. Для `with_ack`
обязателен положительный таймаут в миллисекундах. Повторная регистрация
или подписка заменяет предыдущие настройки для этого соединения.

Для отписки потребитель отправляет
`{"type":"unsubscribe","queue":"HighPriorityQueue"}`. Если у клиента
нет подписки на указанную очередь, брокер возвращает `error`.
Типы сообщений, обработчики которых ещё не реализованы, также дают `error`.

Брокер хранит эти настройки только в памяти по identity сокета ROUTER.
После переподключения с другим identity или перезапуска нужно объявить их
заново. Обработка сообщений, доставка, подтверждения и восстановление по QoS
на этом этапе ещё не реализованы.

## Проверка связи с тестовым клиентом

После сборки из каталога `lab7/build` запусти брокер в первом терминале:

```bash
./broker ../config/broker.yaml
```

В другом терминале перейди в тот же каталог и запусти тестового клиента:

```bash
cd ~/Desktop/NSU_labs_CPP_7-semester/lab7/build
./test_client
```

Клиент создаёт `Envelope` с типом `produce`, именем очереди
`HighPriorityQueue` и содержимым `Привет, брокер!`, преобразует его в JSON
и отправляет на `tcp://localhost:5555`. В терминале брокера должно появиться:

```text
Получен конверт: type=produce, queue=HighPriorityQueue, payload="Привет, брокер!"
```

Клиент должен вывести ответ:

```text
Ответ брокера: type=error, payload="Тип сообщения пока не поддерживается: produce"
```

Для проверки обработки ошибки отправь некорректный JSON:

```bash
./test_client --invalid
./test_client
```

Брокер должен вывести ошибку разбора и затем принять следующий корректный
конверт. На некорректный JSON клиент получит ответ типа `error`. Тестовый
`produce` также получает `error`: помещение в очередь пока не реализовано.

Сообщение клиента об отправке означает только передачу данных сокету ZeroMQ,
а не подтверждение от брокера. Подтверждение разбора приходит отдельно.
`receive()` ждёт без таймаута, поэтому при отсутствии ответа клиент может
ожидать бесконечно. Адрес клиента соответствует порту в примере `config/broker.yaml`;
если изменить порт в конфиге, нужно также изменить адрес в `src/test_client.cpp`.
Для остановки брокера нажми `Ctrl+C` в его терминале.
